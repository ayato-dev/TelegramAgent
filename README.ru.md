# tgagent

[English version](README.md)

ИИ-агент для Telegram, который разворачивается на своём сервере. Отвечает в личных чатах, группах и в
гостевом режиме, ищет информацию в интернете, выполняет Python, читает фото, PDF и голосовые сообщения,
ставит напоминания, создаёт опросы и выполняет задачи из чек-листов Telegram.

Поддерживаемые провайдеры: **Anthropic (Claude), OpenAI, Google Gemini, DeepSeek и Groq**. Достаточно
одного API-ключа; при нескольких ключах каждый пользователь выбирает модель в `/settings`.

Доступ ограничен списком Telegram ID из конфигурации. Интерфейс доступен на русском и английском и
выбирается по языку приложения Telegram у пользователя.

## Быстрый старт

Нужны компьютер или сервер на Linux или macOS с Docker (на Linux установщик может поставить Docker сам), а
также:

1. токен бота от [@BotFather](https://t.me/BotFather) (`/newbot`);
2. свой Telegram ID — его показывает [@userinfobot](https://t.me/userinfobot);
3. хотя бы один API-ключ провайдера. У [Groq](https://console.groq.com/keys) есть бесплатный тариф.

```bash
curl -fsSL https://raw.githubusercontent.com/ayato-dev/TelegramAgent/main/easy-install.sh | bash
```

Скрипт запрашивает эти данные, записывает `~/tgagent/.env` и запускает опубликованный образ (amd64 и
arm64). Данные хранятся в файле SQLite на Docker-томе.

Затем настройте бота в @BotFather → Bot Settings:

- **Group Privacy → Turn off**, чтобы бот видел сообщения в группах. Если бот уже добавлен в группу,
  после изменения удалите его и добавьте снова.
- В мини-приложении настроек BotFather включите **Threaded Mode** (топики в личных чатах) и
  **Guest Mode**.

## Возможности

- **Личные чаты.** Каждый топик — отдельный разговор; топикам без названия бот присваивает название сам.
  `/new` начинает новый разговор. Ответ на одно из прежних сообщений бота продолжает разговор с этого
  места. Ответы выводятся черновиком по мере генерации, с кнопкой «Стоп» и, по желанию, с ходом
  рассуждений.
- **Группы.** Бот читает чат, но отвечает только при упоминании или ответе на его сообщение. Упоминание в
  ответ на чужое сообщение, фото или голосовое добавляет это сообщение и цепочку ответов в контекст.
  Каждый участник, отвечающий боту, продолжает свою ветку. Бот может кратко пересказать обсуждение. Пока
  бот работает, в чате отображается статус «печатает», ответ публикуется одним сообщением.
- **Гостевой режим.** Бота можно вызвать в любом чате, включая чаты, где его нет; он отвечает один раз.
- **Объединение сообщений.** Сообщения, отправленные одним человеком подряд (комментарий и пересланные с
  ним посты, альбом), обрабатываются как один запрос.
- **Пересланные посты.** Пост без вопроса бот разбирает: о чём он, какой контекст в нём опущен, и в конце
  кратко проверяет факты. Если вопрос задан, бот отвечает на него.
- **Инструменты.** Поиск и чтение страниц, выполнение Python (результаты и файлы отправляются в чат),
  напоминания и отложенные задания, опросы, чек-листы Telegram. Модели OpenAI генерируют изображения.
- **Голос и видео.** Голосовые сообщения, видеосообщения, аудио и видео расшифровываются через Groq
  Whisper. Модели Gemini получают аудио и видео напрямую и обрабатывают ссылки на YouTube.
- **Длинные разговоры.** Когда контекст превышает заданный размер, история сокращается до выжимки: у
  Claude это делает API, у остальных провайдеров — бот.
- **`/settings`** — модель, глубина рассуждений, показ рассуждений, поиск, выполнение кода, стиль
  ответов. Настройки хранятся для каждого пользователя и действуют в личных чатах, группах и гостевом
  режиме.
- **`/usage`** — расходы на API по периодам и пользователям.
- **Контроль доступа.** Пользоваться ботом могут только пользователи из `ALLOWED_USER_IDS`. Группа
  разрешена, только если бота добавил один из них; в остальных случаях бот выходит из группы.

- **OpenAI:** генерация изображения (gpt-image-2) — около $0.04; контейнер code interpreter — $0.03 за

- **Регионы:** OpenAI, Anthropic, Google и Groq недоступны в ряде стран, включая Россию. Запросы из таких
  мест завершаются ошибкой региона, о которой бот сообщает пользователю.

## Как снизить расходы

Примеры конфигураций:

| Вариант | Ключи | Стоимость | Ограничения |
|---|---|---|---|
| Бесплатно | Groq | $0 | лимиты бесплатного тарифа Groq; нет обработки изображений |
| Бесплатно, с аудио и YouTube | Gemini, Groq; `DEFAULT_MODEL=gemini:gemini-3.1-flash-lite` | $0 | лимиты бесплатного тарифа Gemini; поиск только через gpt-oss |
| Недорого, все возможности | Anthropic (Haiku 5.5) или OpenAI (Luna), плюс Groq для Whisper | центы в день при обычном использовании | — |
| Недорого вне пика | DeepSeek | $0.15 / $0.60 вне пика | нет поиска и выполнения кода |

Настройки, влияющие на стоимость:

- Глубина рассуждений: уровень «Быстро» уменьшает число токенов рассуждений, которые оплачиваются как
  выходные.
- Поиск: каждый поиск оплачивается и добавляет содержимое страниц во входные токены.
- `COMPACTION_TRIGGER_TOKENS`: более высокий порог увеличивает стоимость каждого запроса в длинных
  разговорах и может перевести запросы на тариф длинного контекста.
- Новые топики или `/new` не дают несвязанной истории попадать в запросы.
- Кэширование промптов включено автоматически. Кэшированный вход дешевле в 50 раз у DeepSeek, в 10 раз у
  Claude и OpenAI, в 2 раза у Groq.
- `/usage` показывает расходы по пользователям.

## Размещение

Бот использует около 300 МБ памяти. В режиме polling (по умолчанию) ему нужен только исходящий доступ в
интернет, публичный адрес не требуется. Сервер должен находиться в стране, которую обслуживают выбранные
провайдеры.

| Вариант | Стоимость | Особенности |
|---|---|---|
| Oracle Cloud Always Free (ARM) | бесплатно | 2 OCPU и 12 ГБ на arm64; при регистрации нужна карта; в популярных регионах часто нет свободных мощностей; простаивающие инстансы могут быть отозваны. |
| Google Cloud e2-micro | бесплатно | 1 ГБ памяти в us-west1, us-central1 или us-east1; достаточно для работы с SQLite. |
| VPS | €4–6 в месяц | Hetzner, OVH, Contabo и аналогичные. |
| Собственный компьютер или Raspberry Pi | бесплатно | Работает, пока устройство включено. |
| Google Cloud Run | бесплатный лимит | Требуется webhook-режим и внешняя база данных. |
| Render, Railway, Fly | бесплатно–$5 | Требуется webhook-режим; бесплатные сервисы засыпают и не имеют постоянного диска, используйте Neon Postgres. |

Некоторые диапазоны IP дата-центров получают от Groq ответ HTTP 403 (Cloudflare). В этом случае смените
провайдера или хостинг.

## Установка

**Docker с SQLite (один контейнер):**

```bash
git clone https://github.com/ayato-dev/TelegramAgent.git && cd TelegramAgent
cp .env.example .env          # укажите токен, ALLOWED_USER_IDS и хотя бы один API-ключ
docker compose -f compose.sqlite.yaml up -d
docker compose -f compose.sqlite.yaml logs -f
```

**Docker с PostgreSQL** (`compose.yaml` запускает PostgreSQL 18 рядом с ботом):

```bash
cp .env.example .env          # дополнительно POSTGRES_PASSWORD (буквы, цифры, «-» и «_»)
docker compose up -d --build
```

Миграции базы данных применяются при запуске. Строка `models: ...` в журнале запуска показывает доступные
модели.

**Без Docker:** Python 3.13 и [uv](https://docs.astral.sh/uv/): `uv sync`, затем
`uv run alembic upgrade head && uv run python -m tgagent`.

### Webhook-режим и serverless-платформы

По умолчанию используется polling. Для платформ, которые предоставляют HTTPS-адрес и останавливают
простаивающие инстансы, используйте webhook-режим:

- `WEBHOOK_URL=https://ваш-адрес` — Telegram отправляет обновления на `<url>/webhook`.
- `PORT` — порт (по умолчанию 8080; большинство платформ задают его сами).
- `WEBHOOK_SECRET` — необязательно; если не задан, вычисляется из токена бота. Задайте явно, если
  используете `/cron`.
- `WEBHOOK_INLINE=true` — обрабатывать каждое обновление внутри HTTP-запроса. Необходимо там, где CPU
  ограничивается после отправки ответа (Cloud Run с оплатой за запросы).

Сервер также отвечает на `GET /health` и `/cron`. Вызывайте `/cron` каждые 1–5 минут с заголовком
`X-Cron-Secret: <WEBHOOK_SECRET>` (или `?secret=<WEBHOOK_SECRET>`), чтобы отправлять наступившие
напоминания и удалять старые журналы групп на платформах, где между запросами ничего не выполняется.

У serverless-инстансов нет постоянного диска, поэтому нужен PostgreSQL. У [Neon](https://neon.tech) есть
бесплатный тариф: `DATABASE_URL=postgresql+asyncpg://user:password@host/dbname?ssl=require`. Neon
приостанавливается после 5 минут простоя; задайте `REMINDER_POLL_SECONDS=600`, чтобы проверки напоминаний
не держали его активным.

**Google Cloud Run.** Cloud Run не загружает образы с ghcr.io, поэтому сначала скопируйте образ в Artifact
Registry (в Cloud Shell уже есть `gcloud` и Docker):

```bash
gcloud artifacts repositories create tgagent --repository-format=docker --location=us-central1
gcloud auth configure-docker us-central1-docker.pkg.dev
docker pull ghcr.io/ayato-dev/telegramagent:latest
docker tag ghcr.io/ayato-dev/telegramagent:latest us-central1-docker.pkg.dev/PROJECT/tgagent/bot
docker push us-central1-docker.pkg.dev/PROJECT/tgagent/bot
gcloud run deploy tgagent --image us-central1-docker.pkg.dev/PROJECT/tgagent/bot \
  --region us-central1 --allow-unauthenticated --max-instances 1 --timeout 600 \
  --set-env-vars WEBHOOK_INLINE=true,REMINDER_POLL_SECONDS=600,WEBHOOK_URL=https://SERVICE-URL \
  --set-env-vars TELEGRAM_BOT_TOKEN=...,ALLOWED_USER_IDS=...,GROQ_API_KEY=...,DATABASE_URL=...,WEBHOOK_SECRET=...
gcloud scheduler jobs create http tgagent-cron --location us-central1 --schedule "*/5 * * * *" \
  --uri https://SERVICE-URL/cron --http-method POST --headers X-Cron-Secret=ВАШ_WEBHOOK_SECRET
```

Адрес сервиса отображается после первого развёртывания; укажите его в `WEBHOOK_URL` и разверните сервис
повторно. API-ключи рекомендуется хранить в Secret Manager (`--set-secrets`), а не в открытых переменных
окружения.

## Настройки по провайдерам

| Настройка | Claude | OpenAI | Gemini | DeepSeek | Groq gpt-oss |
|---|---|---|---|---|---|
| Глубина рассуждений (быстро / обычно / глубоко) | effort low / medium / high | reasoning low / medium / high | thinking low / по умолчанию / high | low / high / max | low / medium / high |
| Показ рассуждений | краткое изложение рассуждений | сводка рассуждений | сводка рассуждений | рассуждения целиком | рассуждения целиком |
| Поиск | поиск и чтение страниц | web search | Google Search (платный тариф) и чтение ссылок | — | browser search |
| Выполнение кода | песочница, файлы отправляются в чат | code interpreter, файлы отправляются в чат | code execution, графики отправляются в чат | — | Python, графики отправляются в чат |
| Сокращение контекста | на стороне API | ботом | ботом | ботом | ботом (с 5K на бесплатном тарифе) |

Кнопка выбора модели в `/settings` показывает модели всех настроенных провайдеров с обозначением их
возможностей. В личных чатах смена модели начинает новый разговор; ответы на прежние сообщения
продолжаются в модели того разговора. Модели, которых нет в таблице, можно указать как `провайдер:модель`;
они получают стандартные возможности провайдера и учитываются в `/usage` по цене $0.

Документы, которые модель не может прочитать сама, преобразуются в текст: из PDF извлекается текст (в том
числе из подписанных ЭЦП), текстовые файлы вставляются без изменений. Остальные двоичные файлы передаются в
песочницу для кода только при работе с Claude.

## Промпты

Папка `prompts/` содержит файлы промптов, которые можно менять без изменения кода:

- `fact-check.md` — правила разбора пересланных постов и проверки утверждений. Добавляется к системному
  промпту.
- `system.md` — шаблон. Пока в нём только комментарий, используется встроенный промпт. Текст, написанный
  после комментария, заменяет встроенный системный промпт.
- `secretary.md` — шаблон для режима секретаря (пока не реализован).

Файлы промптов читаются при запуске. При работе в Docker пересоберите образ или подключите папку:
`-v ./prompts:/app/prompts:ro`. Другое расположение задаётся переменной `PROMPTS_DIR`.

## Конфигурация

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `ALLOWED_USER_IDS` | Telegram ID пользователей с доступом, через запятую |
| `ACCESS_DENIED_TEXT` | Ответ остальным: не задано — короткий отказ на их языке; пусто — без ответа |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `DEEPSEEK_API_KEY`, `GROQ_API_KEY` | API-ключи провайдеров; нужен хотя бы один |
| `DEFAULT_MODEL` | `провайдер:модель`; пусто — самая дешёвая модель первого настроенного провайдера |
| `GROQ_PAID_TIER`, `GEMINI_PAID_TIER` | `true` на платных тарифах |
| `COMPACTION_TRIGGER_TOKENS` | Размер контекста, при котором история сокращается (минимум 50000, по умолчанию 100000) |
| `MAX_OUTPUT_TOKENS` | Максимальная длина ответа (по умолчанию 16000) |
| `DEFAULT_EFFORT` | Глубина рассуждений по умолчанию: low, medium или high |
| `WEB_SEARCH_MAX_USES` | Максимум поисков Claude на один ответ (по умолчанию 5) |
| `WHISPER_MODEL` | `whisper-large-v3` или `whisper-large-v3-turbo` |
| `DATABASE_URL` | По умолчанию `sqlite+aiosqlite:///data/tgagent.db`; PostgreSQL: `postgresql+asyncpg://...` |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Параметры базы данных для `compose.yaml` |
| `WEBHOOK_URL`, `WEBHOOK_SECRET`, `PORT`, `WEBHOOK_INLINE` | Webhook-режим, см. выше |
| `REMINDER_POLL_SECONDS` | Интервал проверки напоминаний (по умолчанию 60) |
| `PROMPTS_DIR` | Папка с файлами промптов (по умолчанию `prompts`) |
| `TIMEZONE` | Часовой пояс для напоминаний (по умолчанию Europe/Moscow) |
| `CHAT_LOG_RETENTION_DAYS` | Срок хранения журналов групп (по умолчанию 30) |
| `LOG_LEVEL` | INFO или DEBUG |

## Архитектура

```
Telegram ──polling или webhook──▶ AccessMiddleware ─▶ обработчики (личные чаты / группы / гость / команды)
                                                         │
                                                         ▼
             TurnService: ветка разговора → сокращение истории → раннер модели разговора
                                │                                │
          SQLite или PostgreSQL ◀┘       Claude / OpenAI / Gemini / DeepSeek / Groq
       (дерево сообщений, журнал групп,           (стриминг, инструменты, медиа)
        напоминания, расходы)                            │
                                          ResponseSink ◀──┘
              (черновики в личных чатах, статус «печатает» и один ответ в группах, гость, напоминания)
```

| Пакет | Содержимое |
|---|---|
| `agent/` | каталог моделей и цены, промпты, инструменты, раннеры провайдеров (`providers/`), обработка ошибок |
| `context/` | преобразование сообщений Telegram, кодирование медиа под провайдеров, работа с PDF, дерево истории |
| `services/` | обработка хода, сокращение истории, остановка, напоминания, инструменты, названия топиков, расходы |
| `telegram/` | обработчики, контроль доступа, рендеринг Markdown, стриминг, webhook-сервер |
| `storage/` | модели SQLAlchemy, репозитории, миграции Alembic |
| `i18n.py` | тексты интерфейса на русском и английском |

Разговор хранится как дерево узлов; контекст запроса — путь от сообщения к корню или к последней выжимке.
Каждый разговор привязан к модели, с которой он начался, а история хранится в собственном формате
провайдера, поэтому рассуждения, подписи и вызовы инструментов передаются провайдеру без изменений.

## Разработка

```bash
uv sync
uv run ruff check src tests migrations && uv run ruff format src tests migrations
uv run mypy
uv run pytest                 # тесты с базой данных используют временный файл SQLite
docker run -d --name tgagent-testdb -e POSTGRES_USER=test -e POSTGRES_PASSWORD=test -e POSTGRES_DB=test -p 55432:5432 postgres:18
TEST_DATABASE_URL=postgresql+asyncpg://test:test@localhost:55432/test uv run pytest
```

Раннеры провайдеров тестируются на фейках и на официальных SDK через подменённый HTTP-транспорт. Новая
миграция: `DATABASE_URL=... uv run alembic revision --autogenerate -m "..."`.

## CI/CD

`.github/workflows/ci.yml` выполняет проверки (ruff, mypy) и тесты на PostgreSQL и SQLite для каждого
pull request и push, собирает мультиархитектурный образ, публикует его в GHCR из `main` и при включённом
деплое разворачивает его.

Развёртывание выполняет self-hosted runner GitHub Actions на сервере. Он подключается к GitHub по
исходящему HTTPS; SSH и входящие порты не требуются. Задание копирует `compose.yaml` и `.env` в
`DEPLOY_DIR`, выполняет `docker compose pull` и `up --wait`, а при ошибке выводит журналы.

Подготовка сервера (однократно):

1. Установите Docker Engine с плагином compose.
2. Создайте пользователя для runner и каталог развёртывания:
   ```bash
   sudo useradd --system --create-home gha-runner
   sudo usermod -aG docker gha-runner
   sudo install -d -o gha-runner -g gha-runner -m 750 /opt/tgagent
   ```
   Членство в группе `docker` равнозначно правам root; используйте выделенный сервер.
3. **Settings → Actions → Runners → New self-hosted runner** (Linux). Установите runner от пользователя
   `gha-runner` и зарегистрируйте его с меткой `tgagent`:
   ```bash
   ./config.sh --url https://github.com/<owner>/<repo> --token <token> --labels tgagent --unattended
   sudo ./svc.sh install gha-runner && sudo ./svc.sh start
   ```

Настройки репозитория:

- Для публичных репозиториев: Settings → Actions → General → «Fork pull request workflows» →
  «Require approval for all outside collaborators», чтобы pull request не мог выполнить код на runner.
  Задание развёртывания запускается только при push в `main`.
- **Settings → Environments → `production`**: разрешите развёртывание только из `main`; ревьюеры —
  по желанию.
- **Secrets:** `TELEGRAM_BOT_TOKEN`, `POSTGRES_PASSWORD` и ключи используемых провайдеров.
- **Variables:** `DEPLOY_ENABLED=true` (без неё развёртывание пропускается), `ALLOWED_USER_IDS`.
  Необязательные: `DEFAULT_MODEL`, `GROQ_PAID_TIER`, `GEMINI_PAID_TIER`, `ACCESS_DENIED_TEXT`, `TIMEZONE`,
  `DEFAULT_EFFORT`, `COMPACTION_TRIGGER_TOKENS`, `WHISPER_MODEL`, `DEPLOY_DIR` (по умолчанию `/opt/tgagent`).


При использовании SQLite сохраняйте том `tgagent_botdata` (файл `tgagent.db`).
